# 泰州方言通 操作手册（给人看）

> 面向开发者的日常操作文档：启动、测试、数据库、模型、构建、部署、协作流程。
> 所有命令在项目根目录 `~/taizhou-voice` 下执行（除非注明）。

---

## 0. 项目结构速览

```
backend/      后端（FastAPI + SQLAlchemy + SQLite），端口 8000
frontend/     前端（Nuxt 4 + Vue 3 + Tailwind），端口 3000
models/       模型权重（不进 git），asr/ 与 tts/ 两级目录
docs/         设计文档与契约（操作手册 / API契约 / 数据模型 / 任务书）
```

- 非 monorepo：前后端平级、各自管理依赖（后端 uv、前端 pnpm）。
- 前端请求 `/api/**` 在开发环境由 Nuxt proxy 转发到后端 `:8000`；部署期靠后端 CORS。

---

## 1. 启动开发环境

开发服务器**统一由你自己手动启动/关闭**（AI 不负责启停）。

```bash
# 终端 1：后端（首次先装依赖）
cd backend && uv sync
uv run uvicorn app.main:app --host 0.0.0.0 --port 8000   # http://localhost:8000

# 终端 2：前端（首次先装依赖）
cd frontend && pnpm install
pnpm dev                                                  # http://localhost:3000
```

- 前端 Nuxt 热更新，改代码即时生效；后端 FastAPI 若要热更新，加 `--reload`。
- 覆盖模型路径/设备（GPU 演示时）：

```bash
QWEN3_ASR_MODEL_DIR=/path/to/model ASR_DEVICE=cuda:0 uv run uvicorn app.main:app --port 8000
```

- 验证后端：`curl http://127.0.0.1:8000/health`（返回 `{"status":"ok","model_loaded":true}`）。

## 3. 数据库（SQLite + SQLAlchemy）

数据库文件在 `backend/data/taizhou_voice.db`（可用环境变量 `TAIZHOU_VOICE_DB` 覆盖）。

- **建表**：`backend/app/db.py` 的 `init_db()` 用 `Base.metadata.create_all` 自动建表（首次启动或手动调用）。
- **种子数据**：27 句句子待接入（源 `hailing_asr/data/metadata.csv`），任务 #2 落地后写一个 seed 脚本。
- **重置**：直接删 `backend/data/taizhou_voice.db` 重新启动即可（无迁移文件，结构以 `models.py` 为准）。

> 表结构见 `docs/数据模型.md`；改模型后删库重建即可（演示期无迁移负担）。

## 4. 模型管理

模型权重放 `models/`（不进 git），按「类型/版本」组织，每个模型目录一个 `model.yaml`：

```
models/
├── asr/asr-v1.0/model.yaml     # Qwen3-ASR
└── tts/tts-v2.0/model.yaml     # CosyVoice2
```

- 激活指针在 `backend/app/main.py`（当前 `QWEN3_ASR_MODEL_DIR` 环境变量 + 默认路径）。
- 换模型：改环境变量 / 默认路径 → 重启后端；旧版本磁盘保留可回滚。
- 完整契约见 `docs/2026-08-19-模型集成规范.md`。

> 注意：当前默认模型路径硬编码 `/home/rat/dialect_asr_system/...`，部署前要迁到 `models/asr/asr-v1.0/`（见后端 review 调整项 #4）。

## 5. 构建与部署

```bash
# 前端构建
cd frontend && pnpm build      # 产出 .output/，可用 pnpm preview 本地预览

# 后端无需构建，直接 uvicorn 跑；GPU 机器需按 README「GPU 场景」装对应 CUDA 版 torch
```

演示部署到游戏本（GPU）：

1. `nvidia-smi` 确认显卡与 CUDA 版本。
2. 后端 `pyproject.toml` 去掉 CPU 版 torch 的 `[tool.uv.sources]`，`uv sync --reinstall` 装对应 CUDA 版。
3. 拷贝模型权重到 `models/asr/asr-v1.0/`（+ `models/tts/tts-v2.0/`），配 `model.yaml`。
4. `ASR_DEVICE=cuda:0` 启动后端，全功能验证（含 TTS）。

> 详见 `README.md` 与后端 review 调整项 #2/#4/#5。

## 7. 协作工作流（重要）

项目采用「**做决策的对话 → 实现对话**」双 Agent 分工（诸葛规则在全局 `~/.config/opencode/AGENTS.md`）：

1. **决策对话**（代号「诸葛」）：
   - 启动咒语「**唤孔明。**」→ 诸葛回「**主公请讲。**」进入决策模式。
   - 只讨论需求、定方案，产出**任务书**到 `docs/YYYY-MM-DD-<topic>-design.md`。
   - 定稿时给**一句话执行 prompt**，不写代码、不启动 dev server。
2. **实现对话**（普通新对话）：
   - 把执行 prompt 复制给它，它读任务书 + 写代码 + 自验。

> 任务书都放 `docs/`（命名 `YYYY-MM-DD-<topic>-design.md`）；改代码前先读对应任务书。
> 前后端改动需交接时，用 `docs/交接文档模板.md` 的格式写一份 handoff 文档。

## 8. 常见问题速查

| 现象 | 处理 |
|------|------|
| `import torch` 报 `_ARRAY_API not found` | numpy 与 torch 版本不匹配，torch 2.7.1 配 numpy 1.x |
| TTS 不可用 / 显存不足 | TTS 必须 GPU，确认 `nvidia-smi` 有显卡、后端 `ASR_DEVICE=cuda:0` 启动 |
| 浏览器录音无反应 | 允许麦克风权限；确认后端装了 ffmpeg |
| 录音格式解不了 | 浏览器 MediaRecorder 产出 webm/opus，需 ffmpeg 转码（调整项 #3） |
| 前端跨域被拦 | 确认后端 CORS 已开（`app/main.py` 的 `CORSMiddleware`），或走 proxy |
| `/health` 显示 `model_loaded:false` | 模型目录不存在或正在后台预热，看后端日志 |
| 换电脑跑不起来 | 先查 torch 是否装成与显卡匹配的 CUDA 版本（见 README） |
