# 泰州方言通（taizhou-voice）项目设计

> 目标：21 号前完成 Web demo，用于比赛演示。只复用模型，代码从零重写。

## 一、项目定位

- **演示阶段**：Web demo，包含「挑战赛 + 转写 + TTS + 音频互转」
- **长期目标**：挑战赛转型为数据集收集工具 + 训练平台（后台管理）
- **核心原则**：只复用模型（wav2vec2-hailing / Qwen3-ASR / CosyVoice2），任何功能代码不参考 hailing_asr 与 dialect_asr_system

## 二、目标用户

- 普通人为主：本地人、方言爱好者、外地想学泰州话的人
- 传播逻辑：比拼谁方言说得标准、谁打分高，乐于分享（朋友间、短视频平台）

## 三、技术栈

| 层 | 选型 |
|---|---|
| 前端 | Nuxt 4 + Vue 3 |
| 后端 | FastAPI (Python) |
| 数据库 | SQLite + SQLAlchemy |
| 音频存储 | 本地目录（后期迁腾讯云 COS） |
| 模型 | Qwen3-ASR（识别/评分）、CosyVoice2（TTS/互转） |
| 部署 | 演示用游戏本（GPU） |

## 四、功能清单

1. **挑战赛**（核心）：刷句子 → 录音 → 评分 → 排行榜
2. **转写**：方言语音 → 普通话文本
3. **TTS**：文本 → 方言语音
4. **音频互转**：方言语音 ↔ 普通话音频

预留：大模型接口、管理后台接口（本次不做，接口留位）。

## 五、首屏设计

- **主入口**：挑战赛（刷句子录音评分，游戏化传播）
- **次入口**：转写 / TTS / 音频互转（并列小入口）
- 整体风格：抖音式卡片滑动 + 百词斩式挑战流程

## 六、数据设计

共用单库 `taizhou_voice.db`：

| 表 | 字段 | 说明 |
|---|---|---|
| sentences | id, text, dialect_text, category, difficulty, created_at | 句子库（27 句种子） |
| users | id, openid, nickname, total_score, created_at | 用户（演示用昵称） |
| recordings | id, sentence_id, user_id, audio_path, score, level, created_at | 录音+评分 |
| translations | id, user_id, source_text, result_text, direction, created_at | 翻译/转写历史 |

音频文件存本地 `data/audio/`，命名 `{sentence_id}_{user_id}_{ts}.wav`，16kHz 单声道。

## 七、开发任务拆分

### 阶段 0：初始化
1. FastAPI 后端骨架（目录结构、依赖、启动脚本）
2. Nuxt 4 前端骨架（页面路由、与后端联调代理）
3. SQLAlchemy 模型定义（四张表）

### 阶段 1：模型服务封装
4. Qwen3-ASR 识别封装（音频 → 文本）
5. CosyVoice2 TTS 封装（文本 → 音频）
6. 评分封装（沿用之前思路：识别文本 ↔ 参考文本相似度打分，后期再优化三维评分）

### 阶段 2：后端 API
7. 句子接口：随机取 N 句（挑战赛用）
8. 录音上传 + 评分接口（音频 → 分数 + 等级）
9. 排行榜接口（实时查询）
10. 转写接口（音频 → 普通话文本）
11. TTS 接口（文本 → 音频返回）
12. 音频互转接口（音频 → 音频）

### 阶段 3：前端页面
13. 首页导航（四功能入口）
14. 挑战赛页：刷句子 → 录音 → 提交评分 → 显示分数/等级
15. 排行榜页
16. 转写页：上传/录音 → 显示普通话文本
17. TTS 页：输入文本 → 播放方言音频
18. 音频互转页：上传音频 → 播放转换结果

### 阶段 4：联调与演示
19. 前后端联调（含模型加载、录音格式转换 16kHz WAV）
20. 游戏本部署 + 演示流程走通

## 八、关键原则与约定

- 评分功能：先沿用旧思路（文本相似度），后期再重新设计三维评分
- 模型解耦：封装成独立 service 层，后期换模型只改 service
- 音频格式：统一 16kHz 单声道 WAV，上传后后端转码
- 存储：先本地目录，路径存库，后期迁 COS 只改读写层
- 大模型/管理后台：接口预留，不实现
