## webm 解码问题修复（调整项 #3）

### 做了什么

浏览器录音产出 webm/opus 格式，libsndfile（soundfile 底层）不支持解码，导致 `Format not recognised` 错误。修复方案：在 ASR 识别前用系统 ffmpeg 把上传音频统一转为 16kHz 单声道 wav。

具体改动：

1. **`backend/app/main.py`**：新增 `_ensure_wav()` 函数 + 在 `asr()` 端点中调用，webm/ogg/m4a/aac/wma 等格式先走 ffmpeg 转码再识别；ffmpeg 失败返回 422 + 明确错误信息；新增临时 wav 文件清理逻辑
2. **`backend/app/routers/score.py`**：同步新增 `_ensure_wav()` + 在 `score()` 端点中调用；`_convert_to_wav()` 改用 ffmpeg 替代 librosa（不再依赖 soundfile 解码 webm）；新增 `subprocess`/`shutil` 导入
3. **`backend/tests/test_asr_webm.py`**（新增）：3 个测试覆盖 `/api/asr` 的 webm 转码路径
4. **`backend/tests/test_score.py`**：新增 `TestScoreWebmTranscode` 类，3 个测试覆盖 `/api/score` 的 webm 转码路径

### 改动文件

| 文件 | 变更 |
|------|------|
| `backend/app/main.py` | 新增 `_ensure_wav()`、`_FFMPEG_ONLY_SUFFIXES`；`asr()` 加 ffmpeg 转码 + wav 临时文件清理 + RuntimeError 处理 |
| `backend/app/routers/score.py` | 新增 `_ensure_wav()`、`_FFMPEG_ONLY_SUFFIXES`；`score()` 加 ffmpeg 转码 + wav 临时文件清理 + RuntimeError 处理；`_convert_to_wav()` 改用 ffmpeg |

## 实时翻译页 v4（细粒度加载状态）

### 做了什么

将原来的单一 `processing` 布尔值拆分为三阶段状态机 `phase: 'idle' | 'recognizing' | 'synthesizing'`，实现更精细的加载反馈：

**状态流转：**
```
idle → (点提交) → recognizing → (ASR 完成) → synthesizing → (TTS 完成) → idle
                                                          ↘ (TTS 失败) → idle（仍入时间线）
```

**UI 反馈：**
- **录音中**：录音按钮变红 + 显示秒数（已有，不变）
- **识别中**：提交按钮显示「识别中…」+ 旋转图标，全部按钮禁用
- **合成中**：提交按钮切换为「合成中…」+ 旋转图标，全部按钮禁用
- **完成**：加入时间线，按钮恢复

**关键改动：**
1. `processing: shallowRef(false)` → `phase: shallowRef<'idle' | 'recognizing' | 'synthesizing'>('idle')`
2. 新增计算属性 `isProcessing = phase !== 'idle'`、`submitLabel`（根据 phase 返回文案）
3. `submit` 函数内 ASR 前设 `phase = 'recognizing'`，ASR 后设 `phase = 'synthesizing'`
4. 录音按钮 `:disabled` 条件使用 `idle`（即 `!anyRecording && !isProcessing`）
5. 提交按钮 `:disabled` 条件使用 `isProcessing`，文案使用 `submitLabel`

| 文件 | 变更 |
|------|------|
| `frontend/app/pages/translate.vue` | `processing` → `phase` 三阶段；新增 `isProcessing`/`submitLabel`；submit 函数分阶段设置 phase；模板按钮文案/禁用逻辑更新 |

- `<main>` 切换 `min-h-0`（功能页）vs 普通 flex-1

## 实时翻译页布局 v2（视觉重构）

### 做了什么

上一版截图诊断发现严重视觉问题：两个录音卡片内 `min-h-[7rem]` 的空预览区占了巨大空间，卡片高度几乎占屏幕一半，时间线被挤压。

   - Row 1（auto）：页头 + 录音按钮行（~48px）
   - Row 2（auto）：预览区（有内容时 ~8rem，无内容时 0）

   - 按钮 h-9 w-9，padding `px-3 py-2.5`
   - 整行高度 ~48px，不再有 7rem 的空占位

3. **预览区独立为共享区域**：
   - `v-show="hasPreview"` — 只要有任一录音完成就显示
   - 内部用 `v-if` 分别渲染泰州话/普通话预览
   - 每个预览：方向标签 + 文件大小 + audio 播放器 + 提交按钮
   - `min-h-[8rem]` 固定高度防跳动

4. **hasPreview computed**：`!!(tzBlob && !tz.isRecording) || !!(ptBlob && !pt.isRecording)`
