## TTS CPU 回退改造（pyttsx3）

### 做了什么

改造 `CosyVoice2Service`，使 TTS 服务在无 GPU 环境下不再报错，而是自动回退到 pyttsx3（系统 TTS）。

**核心改动逻辑**：

1. **`load()` 三级策略**：
   - GPU 可用 → 尝试加载 CosyVoice2（`from cosyvoice.cli.cosyvoice import CosyVoice`，读 `cosyvoice.sample_rate`）
   - CosyVoice2 加载失败或 GPU 不可用 → 回退到 pyttsx3（`pyttsx3.init()`）
   - pyttsx3 也失败 → 抛出 RuntimeError

2. **`synthesize(text)` 两条路径**：
   - CosyVoice2 引擎：走 `inference_sft`（微调说话人 `spk_id="default"`），失败回退 `inference_zero_shot`
   - pyttsx3 引擎：走 `save_to_file` → 临时 wav 文件 → `soundfile.read` 读回 numpy 波形

3. **外部接口不变**：`synthesize(text) → (waveform, sample_rate)`，路由/前端/测试不动

4. **新增 `engine` 属性**：返回 `"cosyvoice2"` / `"pyttsx3"` / `"none"`，供外部判断当前引擎

5. **`is_loaded` 语义扩展**：覆盖 GPU 和 CPU 回退两种情况（`is_loaded` 为 True 即可调用 `synthesize`）

6. **`unload()` 增强**：停止 pyttsx3 引擎（`engine.stop()`）

**pyttsx3 依赖**：`pyproject.toml` 新增 `"pyttsx3>=2.90"`，已 `uv pip install pyttsx3==2.99`

### 改动文件

| 文件 | 变更 |
|------|------|
| `backend/app/services/tts_service.py` | 重写：`load()` 三级策略 + `synthesize()` 双路径 + `engine` 属性 + `_load_cosyvoice2()` / `_load_pyttsx3()` / `_synthesize_cosyvoice2()` / `_synthesize_pyttsx3()` / `_extract_audio_chunks()` |
| `backend/tests/test_tts.py` | 新增 8 个测试：`engine` 初始值、GPU 加载 CosyVoice2、无 GPU 回退 pyttsx3、CosyVoice2 失败回退 pyttsx3、CosyVoice2 合成、pyttsx3 合成、卸载 pyttsx3 |
| `backend/pyproject.toml` | 新增 `pyttsx3>=2.90` 依赖 |

### 遗留问题

- CosyVoice2 实际推理需要在 GPU 环境上验证（`inference_sft` 的 `spk_id` 参数和返回格式可能需微调）
- pyttsx3 的默认采样率因系统而异（通常 22050），需在 GPU 机器上确认
- CPU 回退的语音质量为系统 TTS 水平，无方言效果，仅保证功能可用
