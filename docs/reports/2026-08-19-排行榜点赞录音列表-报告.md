# 排行榜 + 点赞 + 录音列表 三接口实现报告

> 日期：2026-08-19 · 状态：已完成

---

## 做了什么

按 TDD 流程实现三个后端接口：

1. **GET `/api/leaderboard/correct`** — 正确数榜（`score >= 60` 录音数排名）
   - 返回 `rank / nickname / correct_count / total_score / best_score`
   - `?limit=` 默认 20
   - 按正确数降序，同分按 total_score 降序

2. **POST/DELETE `/api/recordings/{id}/like`** — 点赞 / 取消点赞
   - 需登录（`get_current_user` 依赖）
   - 幂等：重复操作返回 200，不报错
   - 录音不存在 → 404
   - 返回 `{ like_count, liked_by_me }`

3. **GET `/api/sentences/{id}/recordings`** — 某句子下录音按点赞数降序
   - 返回 `{ sentence: { id, text, dialect_text }, items: [...] }`
   - 每项含 `recording_id / nickname / audio_url / like_count / liked_by_me`
   - 可选鉴权：带 token 时 `liked_by_me` 反映当前用户状态，否则恒为 `false`
   - 句子不存在 → 404

## 遗留问题与注意事项

1. **CORS 方法已扩展**：`main.py` 的 `allow_methods` 新增 `DELETE`，前端点赞取消请求可正常发出。
2. **可选鉴权模式**：`_get_optional_user` 依赖复用了 `_bearer_optional = HTTPBearer(auto_error=False)` 模式，失败时返回 `None` 而非抛 401，适合「有 token 就个性化、无 token 就默认值」的场景。
3. **SQL 子查询**：排行榜和录音列表均使用了 SQLAlchemy 子查询 + `func.coalesce`，在 SQLite 上验证通过；后续如需迁 PostgreSQL 无需改代码。
4. **`audio_url` 格式**：当前拼接为 `/data/{audio_path}`（如 `/data/audio/1_1_t1.wav`），与前端 proxy 或静态文件挂载路径对齐后可正常播放。
