# 模型集成规范（训练方 ↔ 开发方契约）

> 本文档约定：训练方（队友）产出模型后，如何交付；开发方（我）如何接入。双方照此规范，模型即插即用。

## 一、模型目录规范

所有模型放 `models/` 下，按「类型 / 版本」两级目录组织：

```
models/
├── asr/                  # 语音识别模型
│   ├── asr-v1.0/
│   │   ├── model.yaml    # ★ 必填元数据（契约）
│   │   └── ...           # 权重文件
│   └── asr-v1.1/
│       ├── model.yaml
│       └── ...
└── tts/                  # 语音合成模型
    └── tts-v2.0/
        ├── model.yaml
        └── ...
```

**命名约定**：`{类型}-v{主版本}.{次版本}`，如 `asr-v1.0`、`tts-v2.0`。

## 二、model.yaml 字段（契约）

每个模型目录必须放一个 `model.yaml`，字段如下：

```yaml
type: asr                 # asr / tts（决定用哪个引擎加载）
version: v1.1             # 版本号
engine: qwen-asr          # 加载库：asr 用 qwen-asr，tts 用 cosyvoice
format: transformers      # 权重格式：transformers / cosyvoice 等
dtype: bfloat16           # 推荐推理精度
device: cuda              # 推荐设备（cpu / cuda）
min_vram_gb: 4            # 最低显存要求
trained_by: 钱一          # 训练人
trained_on: 2026-08-20    # 训练日期
data_note: 新增 50 条采集音频微调   # 数据说明
note: 口音更地道了        # 备注
```

**必填**：`type`、`version`、`engine`、`format`。其余选填但建议填全，方便版本管理。

## 三、一个模型「能用」的最低标准

训练方交付前自检，满足才能交付：

1. **能加载**：用 `model.yaml` 里声明的 engine 和 format 能成功加载，不报错
2. **能推理**：跑一条输入，输出格式和接口约定一致
3. **产物完整**：权重文件齐全，不依赖训练机的临时路径

## 四、多版本管理

- **不删旧版本**：所有历史版本保留在磁盘，可随时回滚
- **激活指针**：`config.py` 里 `ACTIVE_ASR` / `ACTIVE_TTS` 决定当前用哪个版本
- **切换**：改激活指针 → 重启后端（卸载旧模型释放显存 → 加载新模型），代码不动

```
config.py:
  ACTIVE_ASR = "asr-v1.1"   # 从 v1.0 切到 v1.1，只改这一行
```

## 五、交付流程（训练方 → 开发方）

1. 训练方训练完成，把模型目录打成压缩包（或放共享盘）
2. 附上 `model.yaml`（按上文字段填）
3. 开发方解压到 `models/{类型}/{版本}/`
4. 开发方改 `config.py` 激活指针
5. 重启后端验证

## 六、注意事项

- 模型权重文件（.safetensors / .pt / .onnx）**不进 git**，走压缩包/共享盘交付
- `model.yaml` 很小，可进 git（但当前 .gitignore 已整体忽略 models/，实际以部署时的约定为准）
- 换设备（CPU→GPU）时，`dtype`/`device` 以 `config.py` 为准，`model.yaml` 里的只是推荐值
