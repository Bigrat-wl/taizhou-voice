## 2. 模型变更明细（旧 → 新）

| 表 | 变更 |
|---|---|
| `users` | 删 `openid`；加 `email`(String 255, unique) + `password_hash`(String 255)；`total_score` Float → Integer |
| `recordings` | 删 `level`；`score` Float → Integer |
| 新增 `likes` | `recording_id` + `user_id`，**联合唯一**（防重复点赞） |
| 全部表 | `created_at` 默认值改上海时区（`models._now`，`datetime.now(ZoneInfo("Asia/Shanghai"))`） |

> 字段含义见 `docs/数据模型.md` §3。改表结构后**删库重建**即可（`backend/data/taizhou_voice.db` 无迁移负担）。

## 3. 接口增量 / 变更（按 API契约 v2）

| # | 接口 | 变更 |
|---|---|---|
| 新增 | `POST /api/auth/register` | 邮箱+密码+昵称 → 201 `{ token, user }`；邮箱撞 → 409 |
| 新增 | `POST /api/auth/login` | 邮箱+密码 → 200 `{ token, user }` |
| 变更 | `POST /api/score` | 改为**需登录**（Bearer token）；请求不再传 `nickname`；响应去 `level`，`score` 为整数 |
| 变更 | 排行榜 | 原 `GET /api/leaderboard` 拆两种：正确数榜 `GET /api/leaderboard/correct` + 点赞数榜 `GET /api/sentences/{id}/recordings` |
| 新增 | `POST /api/recordings/{id}/like` | 点赞（幂等 200） |
| 新增 | `DELETE /api/recordings/{id}/like` | 取消点赞（幂等 200） |

- **正确数判定**：`score >= 60` 计正确数（`COUNT(recordings WHERE score>=60 GROUP BY user_id)`）。
- **点赞数**：`COUNT(likes WHERE recording_id=?)`；榜接口按 `like_count` 降序，带 token 时返回 `liked_by_me`。
- 完整请求/响应示例见 `docs/API契约.md` §1.3–1.7。
